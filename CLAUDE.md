# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

Scripts that turn an OzoneHD T2 WiFi set-top box (Amlogic S805 / Meson8B, armv7, Android 4.4, stock kernel 3.10.33) into a Debian 12 armhf machine. They run from the laptop and reach the box over `adb` and `ssh`. There is no build system or test suite. Everything is bash, busybox `sh` (on the box) and a few dependency-free Python 3 tools. The only way to verify a change is to deploy it to the real box.

Everything (READMEs, comments, script messages, UI labels) is in English.

License: GPL-3.0-or-later with a section 7 permission to combine with the Mali and stock Android libraries (`LICENSING.md`), except `native/gpu/ddx` (MIT, ARM's), `native/gpu/kernel` (GPL-2.0-only, kernel code) and `native/webkit/patches` (BSD-2-Clause, as the WebKit files they change). New code elsewhere is GPL-3.0-or-later; never commit vendor binaries.

- Box: `ssh -i ~/.ssh/id_ed25519_ozone <USER>@<BOX_IP>` (passwordless sudo), or over WiFi at `<BOX_WIFI_IP>` (`-o HostKeyAlias=<BOX_IP>`; both are DHCP reservations on the router), `adb connect <BOX_IP>:5555` (rooted, `su`). The real values are in `.env` (git-ignored; `.env.example` is the template), which `config.sh` reads for the scripts: `box_ip`, `ssh_box`, `scp_box`. Never commit the user name or the addresses: placeholders only.
- Partition backups (boot, recovery, system, misc, logo, cache, the u-boot env, Android's part of data; **not** the bootloader) live in `ozone_backup/backup/` and also in `~/ozone_backup/backup/`, which the scripts read by default; `README.txt` there says what each is. The stock kernel can't read the bootloader (`uboot_read` is a stub; only writing works), so never write `/dev/bootloader`.
- Rescue without Android, while u-boot is intact (env): with the reset button held at power on, u-boot tries USB burning, then `aml_sdc_burn.ini` or `aml_autoscript` on the SD card, then `recovery.img` on the SD card or a FAT USB stick, then the recovery partition. A boot partition it can't load goes the same `recovery.img` way.
- `*/cache/` holds downloaded artifacts (Debian rootfs tarball, SmartTube apk, static armhf busybox). `native/out/` is build output.

## Two phases, one Debian image

Both phases share **the same** Debian rootfs: an ext4 file at `/data/linux/debian.img` on the NAND `data` partition. Any change to files inside Debian must work in both modes.

### `hybrid/`: Debian in a chroot under Android
- `install.sh [size]`: downloads `debian:bookworm-slim` arm/v7 straight from the Docker Hub registry API (no docker), pushes it with `box/*` through adb, then runs `box/install-box.sh` as root on the box. That script creates the image and chroots in to run `box/debian-setup.sh` (groups, user, Dropbear, sysv-rc).
- `box/ozlinux.sh start|stop|restart|shell|status|mount` (installed at `/data/linux/ozlinux.sh`): loop-mounts the image, bind-mounts `/dev`, `/proc` and the rest, copies DNS from Android props, then runs `/etc/ozone/rc`.
- `box/rc`: a minimal init replacement that runs `/etc/rc2.d/S*` in order and **skips** the services listed in `/etc/ozone/native-only`.
- `autostart.sh`: appends the `ozlinux.sh start` hook to stock `/system/bin/preinstall.sh`, which init runs as root after boot. The original is kept at `/data/linux/preinstall.sh.orig`.
- `debloat.sh`: runs `pm disable` on a package list and installs SmartTube. `--undo` reverses it.
- Android 4.4 `adb shell` does not return exit codes, so scripts print a marker (`OZ_INSTALL_OK`) and grep for it.

### `native/`: pure Linux booted by the stock kernel (dual boot)
- `build-recovery.sh [stock boot.img]` → `out/linux-recovery.img`. It takes the stock kernel and header from `boot.img` (via `tools/bootimg.py unpack/pack`, Android boot image v0), extracts `aml_nftl_dev.ko` from the stock ramdisk, and builds a new initramfs with `tools/mkcpio.py` from a spec file, without root or fakeroot. Needs `cache/busybox` (static armhf).
- `initramfs/init`: insmod the NAND driver → mount `/dev/data` → loop-mount `debian.img` → `switch_root` to sysvinit. On failure it saves a log to `/data/linux/native-boot.log`, opens telnet on eth0 for 5 minutes, then reboots, and a plain reboot lands in Android.
- Partition layout: the **boot** partition holds the Linux image (default boot), and **recovery** holds the stock Android `boot.img`. `reboot-android` writes `/run/ozone-reboot-arg`. The diverted `/etc/init.d/reboot` then calls `reboot(RESTART2, "recovery")` via a perl syscall. `prepare-debian.sh` diverts the stock `reboot` and `halt` scripts to `/usr/local/lib/ozone/*.distrib` before deploying the wrappers.
- `prepare-debian.sh <ip>`: copies kernel modules from Android (`8189es.ko`, `aml_thermal.ko`, `mali.ko`) into `/lib/modules/3.10.33/extra`, untars `rootfs/` over `/`, installs sysvinit-core, chrony and related packages.
- `install-desktop.sh <ip>`: deploys a subset of `rootfs/` plus `dotfiles/` (bspwm, sxhkd, polybar, rofi; Catppuccin Mocha), builds `amplay/` on the box, fetches yt-dlp, and adds an X respawn line to `/etc/inittab`. Desktop packages are installed manually first; the list is in `native/README.md`.
- `rootfs/usr/local/bin/ozone-web`: the browser (Python, GTK3, WebKit2 4.1), see `native/README.md`.
- `amplay/amplay.c`: video player for the hardware decoder (amstream ioctls, FFmpeg demux, ALSA audio, evdev keys). Built natively on the box with gcc; there is no cross toolchain. `yt` uses it and falls back to mpv.
- `install-gpu.sh <ip>`: the Mali-450 for X (see `native/gpu/README.md`).
  - Kernel modules come from `gpu/build-modules.sh`, on the laptop with AOSP's `arm-eabi-4.8` and
    the box's own kernel config.
  - The Mali X driver (`gpu/ddx`) and `libEGL.so.1` (`gpu/egl-fix`) are built on the box.
  - `install-games.sh <ip>` adds RetroArch and glmark2 on top.
- `install-logo.sh <ip>`: repacks the `logo` partition (`tools/logoimg.py`, AML_RES v2) with `logo/bootup.png` (1920x1080) and installs the same picture as `/usr/share/ozone/splash.rgb565`, which `ozone-hw` draws on fb0 and `lib/ozone/splash` pulses via the OSD global alpha ioctl until X starts.
- `rootfs/` mirrors absolute paths on the box. `/etc/ozone/is-native` tells the modes apart: it exits 0 when PID 1 is sysvinit and 1 under Android (`/init`). Hardware and input init scripts guard on it so they do nothing in chroot mode.
- Flashing is done from Android as root, manually: `dd if=linux-recovery.img of=/dev/block/boot`, after first copying boot → recovery.

## Kernel and hardware constraints

Several of these were found by bricking or hanging the box. Don't undo them.

- **No systemd, ever.** The kernel has no cgroups, namespaces or overlayfs. apt can quietly swap `sysvinit-core` for `systemd-sysv` through dependencies (e.g. `libpam-systemd`), which causes a boot loop. `rootfs/etc/apt/preferences.d/ozone-no-systemd` pins it at -1. Use `--no-install-recommends` and `dbus-x11`. After any package install, check that `/sbin/init` is still sysvinit.
- **`ANDROID_PARANOID_NETWORK`**: only gid 3003 (`aid_inet`) may open sockets. Daemons that drop supplementary groups (`_apt`, `_chrony`) need `aid_inet` as their *primary* group.
- No `getrandom()` and no seccomp, so Dropbear replaces OpenSSH and chrony runs with `DAEMON_OPTS="-F 0"`.
- `HUNG_TASK_PANIC` and `SOFTLOCKUP_PANIC` are on. `rootfs/etc/sysctl.d/ozone.conf` disables them, as Android does.
- Display: fb0 must be **16 bpp RGB565**. The 32-bit OSD formats have alpha and X writes 0, which gives a black screen; Xorg 21 rejects 24 bpp. `ozone-hw` sets this up. There is no fbcon, so nothing appears on screen before X starts. u-boot picks the output at power-on, analog `576cvbs` when no TV answers on HDMI; `lib/ozone/hdmi-watch` (started by `ozone-hw`) switches to `hdmimode=` once one does.
- **mpv must use `ao=sdl`.** `ao=alsa` sets `silence_size=boundary`, and the Amlogic HDMI audio driver then hangs the kernel. ALSA uses softvol `Master` with no dmix (no mmap), on **device 1 (SPDIF)**: HDMI takes its audio from the SPDIF encoder, and device 0 (I2S) never reaches the TV. Master has no mute switch, so the panel and media keys use `ozone-volume` (mute = volume 0); polybar's internal/alsa shows it as muted for ever. The I2S driver keeps its buffer in blocks of 16 frames (16 L, then 16 R) and converts each write in place, so every write must start and end on a 16-frame boundary, or the TV gets garbage or silence (dmesg `audio data unligned`); amplay writes whole blocks only.
- No working udev. Device permissions are set in `ozone-hw`. Xorg input comes from a generated static config (`gen-xorg-input`). Keyboard hotplug goes through `kbd-merge`, a python-evdev bridge that creates the `ozone-kbd` virtual device through the legacy uinput API, because 3.10 has no `UI_DEV_SETUP`. X only knows `ozone-kbd` from when it started, so `kbd-merge` must never exit (on 3.10 even `close()` of an unplugged device fails with ENODEV; that used to kill it and leave X without a keyboard). Errors go to `/var/log/kbd-merge.log`. Restarting it means restarting X too (`bspc quit`).
- **WiFi:** the 8189ES only appears on SDIO after ioctl `0x6d01` on `/dev/wifi_power` (what Android's `set_wifi_power` does); then `insmod 8189es.ko ifname=wlan0 if2name=p2p0` (`/etc/init.d/ozone-wifi`). Without that the driver loads but finds no card.
- Mainline Linux or Armbian is not an option: NAND sits behind the proprietary `aml_nftl_dev.ko`, WiFi needs the vendor `8189es.ko`, and DVB-T2 tuning runs in userspace Android libs.
- **TV:** `dtvfe` (native/dtv) is a bionic program running the TV app's Android libraries on native Linux (AVL6762 + MxL608 on /dev/i2c-2, reset GPIO 74). It only runs with `/system` mounted and `/dev/__properties__` present (`ozone-android`). `/system` there is a bind mount of `/usr/local/lib/ozone/android`: the 63 Android files native Linux runs (`native/android-files.txt`, found with strace), copied out of the system.img backup by `install-android-files.sh`, so native Linux doesn't read Android's partitions. Anything new that needs a file from Android's `/system` must be added to that list. The logger (`/dev/log/*`) shows a reader other uids' entries only if the reader is in the node's group, so `ozone-dtv` gives the nodes to `video`. Session logs: `/mnt/nand/linux/logs/` (native `tv-*`, Android `android-*`). It is built on the laptop with the NDK (`native/dtv/build.sh`), never on the box. Without an antenna, `ozone-tv --test FILE` feeds a TS into demux0 through dvr0 (`demux0_source=hiu`); the real input is `ts0`. `native/dtv/testmux.py` makes such a file with subtitles, teletext and EIT.
- **TV pipeline:** one `ozone-tv` process owns the tuner (window, player, recordings, timers; later runs hand requests over `~/.local/share/ozone-tv/control`). `dvr0` goes into segment files (`/dev/shm/ozone-tv-live-*`), which `amplay --tv` (commands on stdin, events on stdout) reads behind the writer: that is also the timeshift buffer. amplay is fed the service's PAT/PMT before the data, never probes, and starts at a keyframe. The demux DMA's `asyncfifo0_flush_size` is 256 KB after boot, which delayed a new channel's data by up to 1.3 s: ozone-tv sets 16 KB. libzvbi's `vbi_decode` must get time 0 (as FFmpeg does), or it resets for "lost frames" and no page ever completes. A GTK dialog `run()` from a button's or menu item's handler gets no clicks (the button keeps the pointer grab): ozone-tv opens them with `later()`.
- **Power off can't cut power.** `meson_power_off` reboots (reason `charging_reboot`), so `/etc/default/halt` forces `INIT_HALT=HALT` and `ozone-hw stop` blanks HDMI at runlevel 0 (early suspend, holding the `ozone-halt` wakelock). Deep suspend (`echo mem` without a wakelock) turns the LED red, powers USB down, and only the remote's Power wakes it, **as a cold boot** (no resume). So it is the power off: the diverted `/etc/init.d/halt` remounts everything read-only with SysRq `u` (umountroot leaves the data partition under `debian.img` writable; the diverted `reboot` does the same) and drops the wakelock. Never deep-suspend a running system, as it boots with dirty filesystems. `ozone-standby` holds a wakelock so only Android's early suspend runs. The aml_rtc's sysfs `wakealarm` fails (it reads the alarm back first, which aml_rtc can't), but the `RTC_WKALM_SET` ioctl on `/dev/rtc0` sets it (the RTC's GPO counter); whether it wakes the box from power off is untried, though the TV app's power-on timers count on it.
- The remote's <<, >>, |<<, >>| and Menu send the very same NEC frame (`01 fe 03 fc`, checked on the raw waveform); `work_mode = 1` in remote.conf decodes nothing.
- **IR remote:** the kernel decoder (`aml_keypad`, event0) does nothing until Android's `remotecfg` (the copy on `/system`, see TV) loads a config; `ozone-input` loads `/etc/ozone/remote.conf`, which maps the stock remote to Linux key codes below 248 (X can't see higher ones). `debug_enable = 1` in it logs every frame to the kernel log, the way to find a button's code. `ozone-remote` (X session) grabs the device and passes it on through uinput devices of its own (mouse mode, on-screen keyboard, exit, Power, volume pacing); kbd-merge merges those like any keyboard, and `sxhkdrc` binds the app buttons.
- **uinput** (legacy API, see kbd-merge) takes only the first event of a `write()`: write each event, SYN_REPORT included, on its own, or readers see nothing until a buffer overflows. A virtual keyboard that disappears with a key down left X autorepeating it; kbd-merge now releases a dropped device's keys.
- **XTEST** (xdotool) has its own keyboard with xfree86 key codes unless `setxkbmap` runs after X starts (bspwmrc does); whichever device typed last lends the core keyboard its map, so sxhkd could grab the wrong codes. The session locale is POSIX: xdotool needs `LC_ALL=C.UTF-8` for non-ASCII.
- **Hardware decoder:** `/sys/class/tv/policy_fr_auto` is 1 after boot and must be 0, or closing a decoder oopses the kernel (NULL mode name in `tv_validate_vmode`). Every packet needs `AMSTREAM_IOC_TSTAMP`, or no frame is shown. tsync is forced to audio master by port init and sets pcrscr 3 s behind the first frame; amplay drives pcrscr itself. Late frames are all dropped and the screen stays the color key, so network streams need amplay's rebuffering; after a pause the kernel jumps pcrscr by the paused time. Stream the kernel log over ssh (`dmesg -w`) when testing: oopses reboot the box and the log is lost.
- **Browser:** Chromium can't run (SIGKILL in `execve` on 3.10). WebKitGTK needs `WEBKIT_DISABLE_DMABUF_RENDERER=1` (otherwise it renders via software EGL at ~3 fps). On heavy sites page JavaScript, not painting, limits scrolling, which is why `ozone-web` has per-site JS off ("fast mode") and a reader view. Measure scrolling with real wheel events and on-screen frame changes (`native/gpu/tests/scrolltest.sh`): one `xdotool click --repeat N --delay 30 5`, as an `xdotool` process per step manages only ~10 steps a second, and `screenfps.py` on a grid of points; a JS `scrollBy` loop measures something else.
- **GTK CSS from Python:** the first number in the first stylesheet fails to parse ("not a number: Function not implemented"): GTK reads a stale errno, which Python leaves at ENOSYS (no `getrandom()`). `yt` loads a throwaway stylesheet first.
- **Drawing pictures with cairo (GTK3 on X):** an image surface painted again and again (fades, zooming, animation) is sent to the X server each time and Xorg pays for it (86 % of a core for a GIF): copy it there once with `create_similar_surface` (ozone-photos). bspwm maps some GTK windows that ask for full screen as small floating squares: give them a `state=fullscreen` rule by their class (the capitalised `WM_CLASS` part).
- **Drives and network folders:** `ozone-media` (native only) mounts USB/SD drives in `/media` from netlink uevents (no udev) and keeps the network folders in `/etc/ozone/shares.json` (root, 600: passwords) mounted. The kernel's CIFS speaks **SMB1 only**, and `mount.cifs` needs the `aid_inet` supplementary group (it drops its capabilities, then the paranoid network check fails with error 13). SMB2/3 goes through rclone from rclone.org (Debian's 1.60 creates a stray "．" folder on the share); `rclone mount --daemon` keeps the caller's pipes open, so never capture its output. FUSE mounts (NTFS, exFAT, rclone) are unmounted by `ozone-media stop` before sendsigs. `ozone-media format` erases whole `sd*`/`mmcblk*` disks only; while it runs, `/run/ozone-media/formatting/DISK` keeps the daemon from mounting the half-made drive (the daemon must be restarted after an update, or the old one mounts it twice). mkfs.ext4 1.47's defaults (`metadata_csum`, `orphan_file`) are newer than the kernel.
- **GPU (Mali-450).** The stock kernel has no UMP and no DRM, which the Mali X11 driver needs, so
  `ozone-gpu` loads our own modules from `extra/gpu/`: ump, umplock, mali r5p0 with UMP, hdmi, drm,
  mali_drm, fbump.
  - **Never `rmmod mali`, ours or Android's.** `aml_thermal` keeps polling the GPU cooling device
    of the unloaded module, which oopses, and `panic_on_oops` reboots. Our `mali.ko` refuses to
    unload. To reload the GPU modules, reboot.
  - The module ABI is checked only by vermagic (no MODVERSIONS). Build with
    `gpu/kernel-3.10.33.config`, the box's own config taken from its boot.img.
  - The Mali X driver opens fb1 (OSD2) for its hardware cursor. We use a software cursor, so
    fb1 must stay blanked: unblanked, it shows the 1080p boot logo still in its memory over the
    whole desktop. The stock driver unblanked it at every DPMS On.
  - `gen-xorg-screen` picks `Driver "mali"` when `/run/ozone-gpu` exists. After an X crash with it
    (`/run/ozone-gpu-failed`) it picks fbdev until a reboot.
  - The Mali X driver keeps the screen in a cached UMP shadow: reading the framebuffer is uncached,
    and a window scroll took 47 ms. DRI2 swaps go from the back buffer straight to the framebuffer
    (one copy; 32-bit windows converted with NEON), but only for windows swapping 10+ times a second,
    and their last frame is redone through X after 150 ms: the software cursor restores from the
    shadow, and a stale shadow left trails of the old screen on still GL windows.
  - Programs get the GPU through `ozone-gl` (`/usr/local/lib/mali` first in the library path), never
    system-wide: WebKit/GTK keep Mesa. Desktop OpenGL programs (3D games) go through gl4es with
    `ozone-gl --gl` (`/usr/local/lib/gl4es`, `gpu/build-gl4es.sh`): ~50 times llvmpipe's speed.
  - A screenshot through X misses a GL window that swaps fast (DRI2 swaps go to the framebuffer,
    X's shadow lags): read `/dev/fb0` (RGB565) to see what the screen shows. `/usr/local/bin/mpv` and `retroarch` wrap the real ones.
  - Mali's own EGL is 1.4 with bugs that our `libEGL.so.1` covers (NULL version pointers, no
    platform displays, no core functions from GetProcAddress, DirectColor visuals). The screen is
    16-bit: 8888 configs take 32-bit visuals, which X converts on the CPU, so 565 comes first.
  - `glReadPixels` is 160 ms for 720p. To read GPU results, render into an FBO on an EGLImage of an
    X pixmap (cached UMP) and fetch with XShmGetImage: ~3 ms.
  - RetroArch must use `audio_driver = "sdl2"` (`/etc/ozone/retroarch.cfg`), not alsa, for the
    same HDMI hang as mpv.
  - Our own WebKit (`native/webkit`, `install-webkit.sh`): Debian's source cross-built in docker
    on the laptop, installed in `/usr/local/lib/ozone-webkit` (its helper processes are found by
    the built-in prefix), used only by ozone-web, on the GPU (its default once installed; `OZONE_WEB_GPU=0` for the CPU), with frames as X pixmaps
    (`WEBKIT_X11_PIXMAP_RENDERER`). Rebuild it after each webkit2gtk security update. The build
    container is capped at all but 4 GB of the laptop's RAM: 8 jobs on WebCore once froze it.
  - WebKit on the GPU (ozone-web, either WebKit) runs through the same shims: surfaceless
    display and context, RGBA8 renderbuffers on X pixmaps, readback from UMP. In a process that
    also loaded glvnd's `libGL.so.1` (WebKit), a plain call from the shim binds to glvnd's stubs:
    call libMali through `MALI()`. Link the shim with `--no-as-needed -lMali`, or the dependency
    is dropped and every GL program breaks.
- **Display and sound settings:** `/etc/ozone/display` (written by `ozone-display`); `lib/ozone/set-mode` sets the output mode and the desktop scaler for it (boot, hdmi-watch, ozone-display, amplay's frame-rate matching), `lib/ozone/sound-config` writes `/etc/asound.conf` (HDMI = device 1, analog jack = device 0, the equalizer). With softvol and a float plugin (alsaequal, LADSPA) in one chain, every plug needs format, channels and rate pinned, or ALSA finds no configuration. A running hdmi-watch is the boot-time copy: restart it after changing it.
- GDK key names for media keys have no `XF86` prefix (`AudioStop`, `Launch4`, `Tools`). mpv started with `ao=sdl` can hang on SIGTERM; stop it over its IPC (`quit`), or SIGKILL.
- **Network extras** (`install-network.sh`, see `native/README.md`): iptables must be `iptables-legacy` (nf_tables fails on 3.10); PPPoE is user-space `pppoe` under pppd (no `CONFIG_PPPOE`); the hotspot runs hostapd on `p2p0` (its own phy, AP mode) beside the wlan0 client, dnsmasq as `nobody:aid_inet`; `/run` is `noexec`, so scripts that daemons execute live in `/usr/local/lib/ozone`; WireGuard is `wireguard-go` (never start it with `WG_PROCESS_FOREGROUND=0` set: it forks endlessly). sudo's `secure_path` lacks `/usr/local/bin`: call our tools by full path. Ports: 8080 phone remote (ozone-remote), 49494 + SSDP 1900 DLNA renderer (ozone-dlna), 8008 DIAL for the YouTube app (ozone-cast, sharing SSDP 1900), 8200 DLNA server and 445/139 Samba (ozone-share, when on).
- **Miracast** (`ozone-miracast`, `install-miracast.sh`): the 8189ES needs our own `wpa_supplicant-p2p` (`native/miracast/patches/wpa-rtw-p2p.patch`): it never reports the end of a remain-on-channel, answers probe requests itself with IEs given by the Android command `SET_AP_WPS_P2P_IE`, and deauthenticates removed stations with reason 3, which P2P clients take for the group's end. Listening must stop before `P2P_CONNECT`, or the group forms too late. The system wpa_supplicant (wlan0) stays Debian's.
- **Bluetooth** (`install-bluetooth.sh`, USB adapters only: the box has none): the stock kernel has the Bluetooth stack built in but no `btusb`, which `native/bluetooth/build-btusb.sh` builds from the GPU's kernel tree. bluetoothd needs `[GATT] Channels = 1` (EATT needs 3.14's LE credit-based channels; without it the adapter is dropped). Sound is BlueALSA: `sound-config` routes `default` to the headphones named in `/run/ozone-bluetooth-audio` (written by `ozone-bluetooth agent`), with channels and rate pinned. The agent's questions are rofi: anything that grabs the keyboard (the screensaver) makes rofi give up, which refuses the pairing. Without udev, input nodes made after boot get the input group from `lib/ozone/hotplug` (`/proc/sys/kernel/hotplug`).
- The CPU governor is `interactive` with all cores online (`ozone-hw`); the stock `hotplug` was slower for interactive use.
- **Updates and backups** (`ozone-system`, `native/update.py`): the box updates itself from GitHub's `main` (`/etc/ozone/commit`), so a change reaches it only once pushed. install-desktop.sh and update.py install the user's files only where the user hasn't changed them (sha256 in `/var/lib/ozone/dotfiles.sha256`, git history): the user's own changes (their terminal colours) are kept. A new rootfs file is installed by an update when an install script names it (by path or a folder four levels down): list new files in their install script. Restoring the whole system builds a new `debian.img.new` with the running root's ext4 features and renames it over `debian.img` (the running system keeps the old inode through loop0 until the restart); settings restores and the reset run at the next start from `/etc/init.d/ozone-system`.
- The rootfs is Debian's docker image: `/etc/dpkg/dpkg.cfg.d/docker` keeps `/usr/share/doc`, `man`, `info` and `locale` out of every package installed. A program that needs files from there (Maxima's help index: `etc/dpkg/dpkg.cfg.d/ozone-maxima`; translations, for a Ukrainian interface) needs a `path-include` in a file sorted after it, then a reinstall of the package.
- The root filesystem (`debian.img`) was grown from 2 to 3 GB on 2026-10-29, on the running system: `truncate -s 3G`, `losetup -c /dev/loop0`, `resize2fs /dev/loop0` (online, kernel 3.10). The image is sparse: what Debian fills takes the NAND `data` partition's space, which Android shares; keep an eye on `df -h /mnt/nand` too.
- Run `sync` after deploying files to the box. A crash has left a 0-byte init script before.
- Android's `/system` partition is nearly full and is mounted read-only. Remount it rw only briefly, as `autostart.sh` does (hybrid mode).
